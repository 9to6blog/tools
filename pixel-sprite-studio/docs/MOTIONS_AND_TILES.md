# Pixel Studio — 모션과 Godot 타일셋 사용법

갱신: 2026-09-17. 실행 주소: http://127.0.0.1:3216/

## 어떤 탭을 쓰나요?

| 탭 | 용도 | API 요금 |
|---|---|---|
| API로 새로 생성 | 캐릭터·건물·아이템 한 장 | 생성 버튼을 누를 때 발생 |
| 내 컴퓨터 이미지 변환 | 파일을 지정 크기의 픽셀 PNG로 변환 | 무료 |
| 같은 탭의 AI 시점·자세 변경 | 선택한 파일을 참고해 새 방향·자세로 그리기 | 별도 유료 버튼을 누를 때 발생 |
| 게임 모션 생성 | 기준 캐릭터의 동작 × 방향 시트 생성 | 표시된 요청 수만큼 발생 |
| 시트 재생·내보내기 | 기존 시트 분할, 재생, 프레임 편집, GIF·Aseprite·Godot 내보내기 | 무료, 프레임 AI 수정만 별도 유료 |
| 타일셋 만들기 | 타일 격자·큰 오브젝트·Godot TileSet 구성 | 가져오기·내보내기 무료, 새 AI 생성만 유료 |

화면에서 API 키를 입력하고 **확인·저장**을 누르면 현재 Windows 사용자의 자격 증명 관리자에 보관합니다. 브라우저 저장소, 서버 파일, 작업 메타데이터에는 키를 저장하지 않습니다. API 키 입력란의 **삭제** 버튼으로 Windows 자격 증명에서 즉시 지울 수 있습니다. 기존 버전이 localStorage에 남긴 키는 화면을 열 때 자동 삭제합니다.

## 공통 시점과 팔레트

공통 스타일에서 카메라를 선택합니다. 현재 유지, 눈높이 정면, 횡스크롤 측면, RPG식 내려다보기, 수직 탑다운, 쿼터뷰, 2:1 아이소메트릭을 지원합니다. 캐릭터가 바라보는 방향은 별도입니다. 모션 방향은 동작 표에서 지정합니다.

버튼 선택은 API 프롬프트에 자동으로 들어갑니다. 3D 모델의 정확한 각도 회전은 아니며, 가려진 면은 AI가 새로 그립니다. 단순 무료 픽셀 변환은 카메라·자세를 변경하지 않습니다.

팔레트 프리셋, HEX 목록, GPL/JSON/TXT 파일, 선택 이미지에서 색상 추출을 지원합니다. 고정한 색상 목록은 브라우저에 저장됩니다. API에 색상을 전달한 다음 로컬 후처리에서 불투명 픽셀을 목록의 RGB 중 하나로 매핑하므로 최종 PNG의 사용 색상을 제한할 수 있습니다. 투명도는 별도이며 그림에 따라 목록의 일부 색상만 사용됩니다.

팔레트 고정은 ‘최대 16색’과 다릅니다. 최대 색상은 이미지마다 다른 색을 추출합니다. 고정 팔레트는 여러 이미지가 같은 RGB 목록을 공유합니다. 변경한 설정은 다음 생성·변환·내보내기에 적용됩니다. 이미 저장된 원본은 바꾸지 않습니다.

## 캐릭터 모션 생성

1. **게임 모션 생성** 탭에서 기준 캐릭터를 선택합니다. 저장된 결과 또는 로컬 파일을 사용할 수 있습니다.
2. 공통 카메라를 게임에 맞게 선택합니다. 예: RPG 내려다보기.
3. 몸 크기와 프레임 전체 크기를 정합니다. 예: 몸 32×48px, 칼이 움직일 공간까지 포함한 프레임 96×96px.
4. 동작 × 방향 표에서 필요한 체크박스를 선택합니다. 아래·왼쪽·오른쪽·위 및 네 대각선을 지원합니다.
5. 동작별 프레임 수, FPS, 반복 여부를 정합니다.
6. 버튼 위의 **API 요청 수와 결과 프레임 수**를 확인하고 생성합니다.
7. 결과를 재생해 얼굴·장비·손잡이·발 위치·프레임 경계를 확인합니다.

대기, 걷기, 달리기, 검 베기, 도끼 내려찍기/가로베기, 찌르기, 방어, 피격, 회피, 쓰러짐, 벌목, 채광, 마법, 점프, 직접 지정 동작이 있습니다.

동작·방향 하나당 API에서 시트 한 장을 요청합니다. 6프레임 걷기 4방향은 요청 4회, 결과 24프레임입니다. 전체 묶음을 순차 실행하며 현재 요청 이후 중단할 수 있습니다. 실패 시 자동 재시도하지 않습니다. 완료된 시트는 각각 저장되며, 연결이 끊겨도 저장된 모션 목록에서 다시 추가할 수 있습니다.

고정 팔레트를 정하지 않으면 첫 시트에서 추출한 팔레트를 해당 생성 묶음에 공유합니다. 처음에는 한 방향 걷기 4~6프레임으로 확인하는 것이 좋습니다. AI가 캐릭터 일관성과 정확한 셀 배치를 항상 지키지는 않습니다. 전체 프레임을 독립적으로 트리밍하거나 확대하지 않고, 고정 캔버스를 사용해 흔들림을 줄입니다. 발 위치는 필요할 때 수동 보정합니다.

## 기존 시트를 GIF처럼 재생하기

1. **시트 재생·내보내기**에서 PNG 파일 또는 저장된 원본 시트를 선택합니다.
2. 한 프레임의 가로·세로, 시트 전체 열 수, 가져올 프레임 수를 입력합니다.
3. 필요한 동작의 시작 칸을 지정합니다. 왼쪽 위가 0번이며 가로 방향으로 셉니다. 3열 시트 두 번째 행은 3번입니다.
4. 여백·칸 간격이 있다면 픽셀 단위로 입력합니다. 실제 범위를 벗어나면 처리를 중단합니다.
5. `walk_down` 같은 영문 동작 이름을 입력하고 **시트 분할 후 재생**을 누릅니다.
6. 다른 행도 이름·시작 칸을 바꾸어 추가합니다.

기본은 셀 원래 크기를 유지합니다. 필요하면 모든 프레임을 같은 목표 크기로 변환할 수 있습니다. 움직이는 GIF 자체를 입력하는 기능이 아니라, 정지 PNG/JPEG/WebP 시트를 프레임으로 분할하는 기능입니다.

프레임 편집에서 다음을 조정할 수 있습니다.

- 재생·일시 정지·이전·다음·정수 배율
- FPS, 반복, 개별 프레임의 유지 시간
- 프레임 순서 이동, 복제, 목록에서 제외
- X/Y 위치 이동, 발 기준선(프레임 높이의 85%) 확인
- 타격 프레임 표시
- 특정 프레임에 한해 AI로 다시 그려 교체(유료 1회, 16프레임 이하 동작)

순서를 바꾸거나 프레임을 제외하면 기존 타격 표시는 해제하므로 다시 지정하세요. 위치 이동으로 캔버스 밖으로 나간 픽셀은 내보낼 때 잘립니다. 원본 프레임은 보존됩니다. 편집 목록은 이 브라우저의 localStorage에 저장되며 다른 PC로 자동 동기화되지는 않습니다.

## Godot / Aseprite / RPG Maker 내보내기

**전체 프로젝트 ZIP** 또는 **현재 동작 ZIP**을 누릅니다. 다운로드는 무료 로컬 처리입니다.

```text
pixel_assets/
  sheet.png             전체 아틀라스
  frames/<동작>/000.png  개별 프레임
  gif/<동작>.gif         동작별 재생 파일
  character.aseprite    프레임·시간·태그가 있는 편집 파일
  animations.tres       Godot SpriteFrames
  preview.tscn          Godot AnimatedSprite2D 장면
  metadata.json         위치·시간·동작·타격 프레임
README_ko.txt
```

Godot 4.7.2에서 검증했습니다. `pixel_assets` 폴더를 Godot 프로젝트 루트에 복사하면 `res://pixel_assets/` 경로가 맞습니다. `preview.tscn`을 열거나 `animations.tres`를 AnimatedSprite2D에 넣습니다. Nearest 필터와 발 기준 오프셋이 포함됩니다. `play("walk_down")` 등으로 동작을 실행합니다. 이동·충돌·타격 판정 로직은 게임에서 연결해야 합니다.

Aseprite 파일에는 Artwork 픽셀 레이어와 각 프레임의 cel, 동작별 태그, 시간이 들어 있습니다. 머리·팔·장비를 의미별 레이어로 자동 분해한 파일은 아닙니다. 정지 이미지 결과도 **Aseprite·Godot 내보내기** 버튼으로 단일 프레임 프로젝트로 저장할 수 있습니다.

RPG Maker MZ 걷기 옵션은 `walk_down`, `walk_left`, `walk_right`, `walk_up` 네 동작이 필요합니다. 방향마다 0, floor(N/3), floor(2N/3) 프레임을 골라 3열×4행의 `$Character.png`로 만듭니다. 가운데 패턴은 정지 자세로도 쓰이므로 프레임 순서를 확인하세요. 기본 걷기 규격을 지원하며, 8방향·검·도끼 모션의 실제 실행은 별도 게임 로직/플러그인이 필요합니다. SV 전투 규격 자동 내보내기는 이번 구현 범위에 포함되지 않습니다.

GIF는 10ms 시간 단위와 투명 포함 최대 256색 제약이 있어 원본 PNG/Aseprite와 약간 달라질 수 있습니다.

## 가장 중요한 타일 크기 구분

**128×128은 시트 전체 크기일 수 있습니다. 타일 한 칸 크기가 아닙니다.**

| 항목 | 예 |
|---|---|
| PNG 전체 | 128×128px |
| 타일 한 칸 | 16×16px |
| 시트 배열 | 8열×8행, 64칸 |
| Godot Tile Size | 16×16 |
| Godot Texture Region Size | 16×16 |
| 2×2 오브젝트 | 32×32px 그림을 큰 타일 하나로 등록 |

이 계산은 여백·간격이 0일 때입니다. 16px 타일이 실제로 16px 격자에 맞춰 그려졌는지도 확인해야 합니다. 128px 안에 타일처럼 보이는 그림들이 임의 간격으로 배치되어 있다면, Godot 설정을 16으로 바꾸어도 그림이 정확히 잘리지 않습니다.

현재 프로젝트의 `sprite-128 (6).png`를 확인한 결과 전체 크기는 128px이지만 여러 그림 조각 경계가 16px 격자와 일치하지 않았습니다. `sprite-128 (5).png`는 파일명이 128이어도 실제 캔버스는 여백이 포함된 136×136px입니다. 파일명보다 실제 이미지 크기와 배치를 기준으로 설정하세요.

일반 이미지 모드는 이미지 전체를 하나의 대상으로 축소합니다. 타일 모드는 타일 한 칸 크기와 행·열을 따로 전달하고, 전체 캔버스를 유지하여 그리드가 후처리에서 임의로 이동하지 않도록 합니다. AI 생성의 정확한 이음새와 모든 지형 조합은 여전히 검수가 필요합니다.

## 타일셋 만들기

1. **타일셋 만들기** 탭에서 파일 또는 저장된 결과를 선택합니다. 새 그림이 필요하면 별도의 AI 생성 영역에서 테마를 입력합니다.
2. **타일 한 칸** 가로·세로를 지정합니다. 16×16이 기본입니다.
3. 행·열, 원본 여백, 칸 간격을 지정합니다. **원본 크기로 행·열 계산**으로 채울 수도 있습니다.
4. 오른쪽 격자가 그림 경계와 일치하는지 확인합니다. 범위를 벗어나면 등록·내보내기를 막습니다.
5. 큰 오브젝트는 왼쪽 위 칸 선택 → 묶음 가로 2·세로 2 → 등록 순으로 묶습니다. 겹치는 묶음은 허용하지 않습니다.
6. 선택하지 않은 불투명 칸은 1×1 타일로 자동 등록합니다. 완전 투명 칸은 제외합니다.
7. 필요하면 막힘 타일에 사각형 충돌을 지정합니다. 기본 바닥에는 충돌을 넣지 않습니다.
8. 중심 바닥 타일을 선택하고 **3×3 반복 미리보기**에서 경계를 확인합니다.
9. **Godot 타일셋 ZIP**을 다운로드합니다.

큰 타일로 묶으면 Godot에서 큰 그림 전체가 한 번에 선택됩니다. 맵의 논리 셀 크기는 계속 16px입니다. 4개의 독립된 맵 셀로 구성된 패턴을 칠하려면 2×2를 한 타일로 묶지 말고 1×1 타일 네 개를 선택해 패턴으로 사용하세요.

지형 자동 연결은 고급 옵션입니다. 1×1 타일을 선택하고 같은 지형이 이어지는 주변 방향의 비트를 켜서 등록합니다. 중앙 바닥은 모두 켜고, 바깥 경계 쪽은 끕니다. 한 지형과 빈 영역 사이의 연결을 지원합니다. 모든 안쪽·바깥쪽 코너 조합이 없으면 자동 연결 결과에 빈틈이 생길 수 있습니다. 잔디·물·흙 등 여러 지형 간의 자동 전이 전체를 추정하는 기능은 아닙니다.

타일 ZIP에는 다음이 들어 있습니다.

```text
pixel_tiles/
  atlas.png               여백·간격을 제거해 정리한 새 시트
  atlas.aseprite          편집 가능한 단일 레이어 아틀라스
  tileset.tres            타일 규격·큰 오브젝트·충돌·지형 비트
  paint_here.tscn         TileMapLayer가 연결된 빈 맵 장면
  individual/tile-X-Y.png 개별 타일
  objects/object-X-Y.png  묶음 오브젝트
  layout.json            셀과 오브젝트 구성 정보
source/original.png      입력 이미지 보존본
README_ko.txt
```

타일의 Aseprite 파일은 픽셀 아틀라스이며 Aseprite native tilemap 형식은 아닙니다. Godot에는 native TileSet 리소스를 제공합니다.

## Godot에서 선택·칠하기

1. ZIP의 `pixel_tiles` 폴더를 Godot 프로젝트 루트에 복사합니다.
2. `pixel_tiles/paint_here.tscn`을 엽니다.
3. 씬 트리에서 **Ground (TileMapLayer)**를 선택합니다.
4. 아래쪽 **TileMap** 탭에서 원하는 타일을 고르고 2D 화면에 왼쪽 클릭으로 칠합니다. 오른쪽 클릭은 지우기입니다.
5. Ctrl+S로 씬을 저장합니다.

**TileSet 탭은 규격·충돌·연결을 설정하는 곳, TileMap 탭은 맵을 칠하는 곳입니다.** 기존 맵에는 `tileset.tres`를 TileMapLayer의 Tile Set 속성에 넣으면 됩니다. PNG 전체 크기를 Texture Region Size에 넣을 필요가 없습니다.

기존 프로젝트의 저장되지 않은 씬을 이 도구가 수정하지 않습니다. 저장된 `.tscn`이 있어야 기존 씬의 잘못된 타일 설정을 파일로 점검할 수 있습니다.

## 코드 구조와 데이터 흐름

모션 생성은 기준 PNG → OpenAI 편집 → 반환 원본 저장 → 셀 분할 → 공통 팔레트/고정 캔버스 변환 → 프레임 저장 순서입니다. 이후 재생·편집·내보내기는 저장된 프레임으로 처리합니다. API 원본과 참조 이미지는 작업 폴더에 별도 보존합니다. 키는 작업 메타데이터에 포함되지 않습니다.

Aseprite는 공식 파일 규격의 128바이트 헤더, 레이어·태그·팔레트 chunk, 프레임별 zlib RGBA cel을 기록합니다. Godot SpriteFrames에는 개별 프레임을 가리키는 AtlasTexture, FPS, 반복, 상대 지속시간을 기록합니다. 모든 내보내기의 픽셀은 같은 로컬 프레임에서 가져옵니다.

## 검증과 현재 한계

- 자동 테스트 16개 통과: 기존 픽셀 변환, 팔레트, 시트 경계·간격, 위치 이동, GIF 시간, Aseprite cel, RPG Maker 배열, 타일 묶음·범위, 참조 API 요청·중복 방지.
- Godot 4.7.2 실제 헤드리스 검사 20항목 통과: SpriteFrames/장면 로드, FPS·반복·시간, 16px 규격, 61개 타일(64칸 중 2×2 하나 묶음), 충돌, 지형 비트, 실제 맵 셀 배치.
- Aseprite 1.3.18.5에서 12프레임·4태그를 읽고 PNG로 내보낸 뒤 원본 프레임과 픽셀 차이 0 확인.
- HTTP 무료 업로드·분할·ZIP 테스트에서 기존 사용자 작업 36개 보존 확인.
- 실제 브라우저에서 시트 분할, 재생 프레임 변경, FPS·위치·타격 표시, ZIP 다운로드 확인.
- 테스트 중 유료 이미지 API 호출은 하지 않았습니다. 참조 API 요청 형식은 가상 응답으로 검증했으며, 실제 AI의 자세 품질·일관성·시트 경계는 사용 결과를 확인해야 합니다.

모션 한 요청은 1~16프레임, 시트 가져오기는 한 번에 1~256프레임입니다. 전체 내보내기는 최대 512프레임·1,677만 픽셀로 제한합니다. 큰 자산은 동작별로 나누어 내보내세요. 타일 한 칸은 1~1024px, 한 번에 최대 4096칸, 원본은 1,677만 픽셀입니다. 새 생성의 최종 시트는 기존 이미지 한 변 4096px 제한을 따릅니다.
