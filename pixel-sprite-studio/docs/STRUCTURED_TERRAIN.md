# Pixel Studio 규격형 타일셋 사용법

작성: 2026-09-17

이번 기능은 AI 이미지의 전체 배치를 믿고 잘라 쓰던 문제를 보완합니다. 타일의 연결 형태를 프로그램으로 정한 뒤, 기본 질감 또는 사용자가 고른 이미지의 질감을 입힙니다. 생성·검사·내보내기는 로컬 처리이며 OpenAI API를 호출하지 않습니다.

## 바로 사용하기

1. http://127.0.0.1:3216/ → **타일셋 만들기 → 규격형 자동 연결**.
2. **좁은 길 16종** 또는 **넓은 지형 47종**을 고릅니다.
3. 타일 한 칸 크기를 고릅니다. 8~128px의 짝수를 지원하며 16, 32, 48, 64, 128px 바로가기 버튼이 있습니다.
4. **규격형 타일 만들기 · 무료**를 누릅니다. 기본 질감으로 바로 시험할 수 있습니다.
5. 오른쪽 24×16칸 시험 지도에서 드래그해 칠합니다. 마우스 오른쪽 버튼 또는 ‘바닥으로 지우기’로 지우고, 되돌리기·시험 지도·전체 지우기를 사용할 수 있습니다.
6. 연결 검사와 전체 모습을 확인하고 **Godot + Aseprite 타일맵 ZIP**을 다운로드합니다.

설정을 변경하면 기존 결과에 변경 알림이 표시되며, 다시 생성·검사하기 전에는 내보내기가 비활성화됩니다. 시험 지도에서 그린 모양은 ZIP의 미리보기 장면과 Aseprite 지도에 반영됩니다.

## 기존 이미지 / AI 생성 결과 활용

‘내 이미지 / AI 결과에서 질감 가져오기’를 펼쳐 이미지를 선택합니다. 파일 업로드와 저장된 AI 생성 결과를 모두 지원합니다.

- ① 바닥 영역: 잔디처럼 바탕 재질만 있는 곳을 클릭합니다.
- ② 길·지형 영역: 흙처럼 칠할 재질만 있는 곳을 클릭합니다.
- 선택 사각형 크기를 조절해 모서리, 그림자, 다른 재질이 섞이지 않도록 합니다.
- 선택하지 않은 재질은 색상 선택기의 기본 질감으로 채웁니다.
- 공통 고정 팔레트가 있다면 모든 최종 타일에 적용합니다.

기존 이미지의 길을 자동 인식해서 복원하는 기능은 아닙니다. 사용자가 고른 재질을 새로운 연결 규격에 맞춰 조립합니다. 선택 영역에 굵은 그림자나 경계가 들어가면 반복 띠가 생길 수 있으므로 시험 지도에서 확인하세요.

## 전체 시트와 한 칸 크기

16px 타일 기준:

| 규격 | 그림 수 | 시트 크기 | 칸 배치 |
|---|---:|---:|---:|
| 좁은 길 | 연결 16종 + 바닥 1종 = 17개 | 128×48px | 8열×3행, 남은 칸 투명 |
| 넓은 지형 | 연결 47종 + 바닥 1종 = 48개 | 128×96px | 8열×6행 |

Godot의 Tile Size와 Texture Region Size는 둘 다 **16×16px**입니다. 128px을 입력하는 곳이 아닙니다. 내보낸 TileSet 리소스에는 이미 올바르게 설정돼 있습니다.

## Godot에서 사용

1. ZIP의 **pixel_terrain** 폴더를 프로젝트 루트에 복사합니다.
2. 내부 **road16** 또는 **blob47** 폴더의 **preview_map.tscn**을 열어 시험 지도를 확인합니다.
3. 실제 작업은 같은 폴더의 **paint_here.tscn**을 엽니다.
4. **Ground** 노드 선택 → 하단 **TileMap → Terrains**.
5. **Base** 지형으로 먼저 바닥을 채운 다음 **Path** 지형을 **Connect** 모드로 칠합니다.
6. 지울 때는 Base로 덮습니다. 주변 연결이 함께 바뀝니다.

기존 TileMapLayer에는 해당 폴더의 **tileset.tres**를 지정하면 됩니다. PNG만 다시 등록하면 자동 연결 정보가 따라오지 않습니다.

시험용 preview_map.tscn은 스크립트가 저장된 시험 지도를 복원합니다. 그 장면에서 실제 게임 맵을 편집하지 말고 paint_here.tscn을 사용하세요. 길과 넓은 지형은 서로 다른 하위 폴더에 있어 함께 가져올 수 있습니다. 같은 규격을 재출력해 같은 위치에 복사하면 기존 결과를 갱신하므로 필요한 이전 파일은 별도로 보관하세요.

## Aseprite 파일

- **aseprite/tileset.aseprite**: 실제 Tilemap Layer와 Tileset을 가진 타일 목록.
- **aseprite/preview_map.aseprite**: 같은 타일을 재사용해 구성한 시험 지도.
- Aseprite의 예약된 빈 타일은 인덱스 0입니다. PNG/JSON의 타일 0은 Aseprite에서 1로 대응합니다.
- Draw Pixels → Manual 모드로 수정하면 타일 순서를 유지할 수 있습니다.
- 수정한 그림은 연결 검사를 다시 해야 합니다. Aseprite의 수정이 Godot에 자동 동기화되지는 않습니다.

현재 PC에서는 Aseprite CLI와 Lua 스크립트를 사용합니다. MCP 연결 여부와 무관하게 실행할 수 있습니다. 다른 PC에서는 Aseprite를 설치하고 필요하면 서버 실행 전 ASEPRITE_PATH 환경 변수에 실행 파일 경로를 설정하세요. Aseprite를 찾지 못하면 ZIP 출력에 명확한 오류를 표시하며, 네이티브 파일이 없는 ZIP을 완성품으로 내보내지 않습니다.

## 연결 검사가 확인하는 것

- 길 16종 또는 정규화된 Blob 47종이 모두 존재하는지.
- 겹치는 두 3×3 이웃 영역, 즉 4×3칸의 가능한 배치 4,096가지를 열거합니다.
- 그 배치에서 발생할 수 있는 고유 수평·수직 타일 쌍을 뽑아 경계 RGBA를 비교합니다.
- 길은 162쌍, 지형은 392쌍을 검사합니다. 연결 실패 결과는 출력하지 않습니다.
- 색상 팔레트가 너무 비슷해 여러 타일 그림이 같아지면 별도 경고합니다.

경계 검사는 미적 품질 점수가 아닙니다. 타일 내부의 반복감·너무 규칙적인 무늬·작은 크기에서의 가독성은 시험 지도를 보며 판단해야 합니다. 정사각형 탑다운 지형용이며, 계단식 높이·아이소메트릭 절벽·여러 재질 사이의 모든 전환을 자동 생성하지는 않습니다.

## 코드 구조

- `src/lib/terrain-rules.ts`: 방향 비트, 16/47종 마스크, 지도에서 타일 선택. 브라우저와 서버가 공유합니다.
- `src/lib/terrain.ts`: 재질 자르기·질감 생성·공유 경계·규격 도형 조립·모든 유효 연결 검사.
- `src/lib/terrain-export.ts`: Godot의 2개 지형과 연결 비트, 시험 장면, Aseprite CLI/Lua로 네이티브 타일맵 생성, ZIP 포장.
- `src/app/api/terrain/route.ts`: 로컬 미리보기와 출력 요청. 유료 이미지 API 호출 없음.
- `src/components/terrain-studio.tsx`: 종류·크기·질감 선택, 그리기·지우기·되돌리기, 검사 결과와 다운로드.
- `tests/terrain.test.ts`: 크기별 경계, 마스크, 깨진 경계 검출, 고정 팔레트, 입력 검사.
- `tests/verify-terrain-native.ts`, `tests/verify-terrain.gd`: 실제 Aseprite 재출력과 Godot 지형 선택 검사.

검증: 전체 자동 테스트 26개 통과. 실제 Godot에서 두 규격 각각 256가지 주변 배치의 타일 선택과 256가지 지우기 결과를 확인했습니다. Aseprite의 타일셋·시험 지도를 PNG로 다시 출력한 결과는 각 원본과 픽셀 단위로 일치했습니다.

다른 PC에서 네이티브 검사를 재현하려면 Aseprite와 Godot을 설치하고 아래 순서로 실행합니다. 실행 파일의 실제 위치에 맞춰 환경 변수를 지정하세요. 산출물은 `test-artifacts/terrain/`에 저장되며 GitHub에는 포함하지 않습니다.

```powershell
$env:ASEPRITE_PATH = 'C:\Program Files\Aseprite\Aseprite.exe'
$env:GODOT_PATH = '설치한 Godot 콘솔 실행 파일의 전체 경로'
npx.cmd tsx tests/export-terrain-demo.ts
npx.cmd tsx tests/verify-terrain-native.ts
```

기본 예제는 프로그램이 만든 질감을 사용합니다. 자신의 아틀라스로 검사하려면 `$env:TERRAIN_SOURCE_IMAGE`에 PNG 경로를 지정하세요. 기본 추출 영역은 바닥 `(0,0,16,16)`, 길 `(62,33,8,8)`이므로 해당 영역이 들어 있는 이미지를 사용하거나 스크립트의 영역을 조정해야 합니다. 앱을 실행한 상태에서는 `node tests/http-terrain.mjs`로 HTTP 출력도 검사할 수 있습니다.
